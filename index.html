Embedded Linux — Buildroot & Yocto Project

Buildroot

  • Defconfig → menuconfig / nconfig workflow
  • Toolchain, kernel, bootloader, rootfs in one build graph
  • Custom packages via BR2_EXTERNAL trees
  • Post-build/post-image scripts, overlays, read-only root
  • Size/speed tradeoffs: BusyBox vs full userland, static vs dynamic
  • License compliance manifests (legal-info)
  • When to choose: fixed hardware, fast iteration, smaller teams

Yocto Project / OpenEmbedded

  • Layer model: meta-*, bblayers.conf, priority
  • Recipes (.bb), append files (.bbappend), bitbake tasks
  • Machines, distros, IMAGE_FEATURES, packagegroups
  • Poky reference distro; BSP layers for vendor boards
  • SDK (bitbake -c populate_sdk) for app teams
  • OTA hooks (RAUC, Mender — integration awareness)
  • When to choose: multi-product, long life cycle, reproducible SBOM/supply chain

Shared embedded Linux practice

  • Kernel config fragments, device trees, out-of-tree drivers
  • systemd units for field services; journald remote logging
  • Cross-compilation vs native build in image
  • Hardening: read-only FS, minimal attack surface, no root login
  • Field update discipline aligned with security research findings

Network engineering

Design, implement, and troubleshoot connectivity for servers, plant equipment, and embedded gateways — not just “it works on my laptop.”

Foundation (OSI / TCP/IP)

  • L2 — Data link

    • Ethernet, MAC, ARP, VLANs (802.1Q), trunk/access
    • Switch concepts: CAM tables, STP awareness
    • Link aggregation basics; industrial Ethernet notes

  • L3 — Network

    • IPv4/subnetting, CIDR, VLSM, static routes
    • IPv6 addressing, SLAAC, dual-stack pitfalls
    • ICMP diagnostics; path MTU issues

  • L4–L7 — Transport & apps

    • TCP vs UDP; ports; connection states
    • DNS (records, TTL, split-horizon), DHCP, NTP
    • HTTP/S, TLS handshakes, SNI, cert chains
    • Reverse proxies, load balancing, health checks

Design & operations

Architecture patterns

  • Flat plant network vs segmented OT (DMZ, VLAN by function)
  • NAT, port forwarding, hairpin issues on edge routers
  • Site-to-site and remote access: WireGuard, IPsec awareness
  • Cloud VPC: public/private subnets, security groups, NACLs
  • CDN / reverse proxy in front of origin (Cloudflare, nginx)

Security on the wire

  • Firewall policy: default deny, least privilege (ufw, nftables, cloud SG)
  • 802.1X awareness; guest vs production SSIDs
  • TLS termination, HSTS, cert lifecycle (Let’s Encrypt, internal CA)
  • Network detection: rogue devices, unexpected lateral movement

Troubleshooting methodology

  • Layered isolate: physical → L2 → L3 → DNS → app
  • ping, traceroute, mtr, ss/ip
  • tcpdump / Wireshark: filters, follow TCP stream
  • nmap (scoped), iperf3 throughput/latency
  • Document topology; baseline before/after changes
  • Shell one-liners and scripts for repeatable captures (pcap, routes, DNS)

Security research

Systematic offensive analysis in service of defense — scoped, reproducible, and tied to remediations you can ship. Applies across web, cloud, network, firmware, and embedded Linux.

Research methodology

  1. Scope & authorization — rules of engagement, assets in/out, staging vs prod boundaries.
  2. Recon & mapping — attack surface inventory (hosts, APIs, wireless, serial, admin UIs).
  3. Threat modeling — STRIDE, abuse cases, data-flow diagrams, trust boundaries.
  4. Vulnerability analysis — manual + tool-assisted; chain weak findings into impact.
  5. Exploitation & proof — minimal PoC; demonstrate confidentiality/integrity/availability impact.
  6. Remediation — patch, config, architecture; verify with regression tests in CI.
  7. Disclosure & learning — coordinated timeline, CVE where applicable, postmortem, runbook/RTM updates.

Domains & vulnerability classes

  • Web & API

    • OWASP Top 10, ASVS levels, API Top 10
    • Injection (SQL, NoSQL, command, template)
    • Broken auth, session fixation, JWT misconfig
    • IDOR, mass assignment, excessive data exposure
    • SSRF, XXE, deserialization (where applicable)
    • CSRF, clickjacking, CORS misconfiguration
    • Business logic flaws, race conditions

  • Cloud & platform

    • IAM overprivilege, key leakage, OIDC misbind
    • Public buckets, snapshot exposure, metadata SSRF
    • K8s RBAC, exposed dashboards, secrets in manifests
    • Container escape awareness; image trust & SBOM
    • CI/CD poisoning, pipeline secret exfiltration

  • Network

    • Segmentation bypass, flat OT risks
    • MITM prerequisites, TLS downgrade, cert validation
    • SNMP/legacy mgmt defaults, Telnet/HTTP admin
    • DoS/resilience testing (scoped); rate limits
    • Wireless: rogue AP, weak WPA, guest bleed

  • Embedded / OT / Linux

    • UART/JTAG left enabled, firmware dump & modify
    • Hardcoded creds, default SNMP/Modbus
    • Unsigned updates, supply chain in Buildroot/Yocto layers
    • Kernel/userspace CVE exposure on long-lived images
    • Physical tamper surfaces; safe failure modes

Ethics & legal boundaries

Research only on systems I am authorized to test. No unauthorized access to third-party production. Coordinated disclosure, proportionate PoCs, and privacy-aware reporting. Security findings feed the open DevSecOps curriculum (Parts 21–25, 45–46).

Soft skills & professional practice

Technical depth only matters if you can align people, clarify risk, and deliver under real constraints — especially solo or across plant, office, and remote teams.

  • Communication

    • Explain risk and tradeoffs to non-technical stakeholders
    • Write clear incident updates (SEV, impact, ETA, next steps)
    • Security findings reports: impact, reproduction, remediation priority
    • Documentation others can operate from (runbooks, RTM, ADRs)

  • Collaboration & leadership

    • Cross-functional work: dev, ops, production floor, vendors
    • Requirements elicitation — turning vague asks into testable specs
    • Mentoring via open guides and structured study paths
    • Blameless postmortems; focus on systems not shame

  • Execution & judgment

    • Decompose large problems (epics, spikes, MVPs)
    • Prioritize under fixed time: Must/Should/Won’t framing
    • Ownership from idea → deploy → monitor → fix
    • Calm troubleshooting under outage pressure

  • Integrity & professionalism

    • Ethical security research and honest scope boundaries
    • Respect for safety on plant/OT systems (fail-safe first)
    • Confidentiality for private org and customer data
    • Continuous learning — teach publicly, learn privately from failures
